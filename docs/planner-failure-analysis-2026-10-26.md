## 실제 출력과 실패 단계

첫 출력:

```json
{"action":"new","patch":{"target":{"kind":"organization","value":"가전팀"},"fields":[],"metrics":[]}}
```

조직이라는 종류는 추출했으나 지표와 기간은 누락했다. operation을 생략하여 상태 엔진의 기본값 list가 유지됐다. 첫 출력에 대해 현재 검증기를 재실행한 오류는 다음과 같다. 원본 로그는 각 수정 시도의 오류 대신 마지막 오류만 보존하므로, 아래는 **오프라인 재구성 결과**다.

1. List requires fields, without metrics/grouping
2. Target not in supplied catalog: organization
3. A bounded datetime range is required

두 번째와 세 번째 출력은 동일하다.

```json
{"action":"clarify","patch":{"fields":["broadcast_count"],"metrics":[]}}
```

최종 저장 오류는 `Clarification requires a question`이다. 확인 질문 문장이 없고, 지표 ID인 broadcast_count를 원본 컬럼용 fields에 잘못 넣었다. 이 단계는 턴 형식 검증에서 중단되어 해당 fields에 대한 계획 검증까지 진행하지 않았다.

따라서 마지막 오류만 보면 재질문 형식 문제로 보이지만, 그 이전부터 조회 의도를 실행 가능한 구조로 완성하지 못하고 있었다.

## 코드에서 확인된 설계 문제

1. 턴 스키마는 action만 필수다. new에서 필요한 계획이 비어 있어도 첫 턴 스키마를 통과하고 뒤의 계획 검증에서 거절된다. clarify의 question 필수 조건도 생성 스키마가 아닌 사후 JS 검사에 있다.
2. fields와 metrics는 임의 문자열 배열이다. 컬럼 ID/지표 ID를 뒤바꾼 응답을 생성 단계에서 제한하지 못한다.
3. 시스템 프롬프트에는 mode 인자가 있지만 실행이 가짜 데이터라는 문장이 고정돼 있다. 실제 bootstrap의 live 실행 안내와 모순된다. 이 모순이 이번 오류의 직접 원인인지는 입증되지 않았다.
4. 상태 엔진의 기본 operation=list가 누락된 operation을 채워, 집계 의도 누락이 목록 오류로 나타난다. 집계 여부를 JS가 사용자 문장으로 재해석해서 보정하면 안 된다.
5. 실패 로그는 시도별 validation을 보존하지 않아 마지막 오류가 앞선 실패 이유를 가린다. resolvedState도 마지막으로 검증한 후보일 뿐, 실제 유지된 대화 상태와 같다고 보장할 수 없다.
6. 일반 대화 응답 action이 없다. 모든 입력을 조회/수정/확인/취소/재질문으로 처리하도록 제한해 둬서, 인사나 앱 상태 질문도 이 중 하나로 억지 분류될 수 있다. 앞선 대화의 이상한 취소 응답은 Qwen 성능 외에 출력 계약 자체도 점검해야 한다.

## 판단과 다음 순서

이번 사례에서는 자연어를 전혀 이해하지 못했다기보다 **조직만 부분 추출하고, 제공된 지표·날짜·출력 계약을 연결하지 못했다**는 것이 관찰된 사실이다. 카탈로그 검색 실패나 BI 실패로 분류하면 부정확하다. 1.7B 모델 자체의 한계인지 프롬프트/스키마 구성의 영향인지는 분리 실험 전에는 확정하지 않는다.

다음 개선은 표현별 JS 분기나 문장→지표 대응표 추가가 아니라 다음 순서가 적절하다.

1. 시도별 입력·출력·스키마 오류·계획 오류·도구 결과·시간을 한 묶음으로 기록해 실패 단계를 보존한다.
2. 실행 모드 모순을 제거하고 일반 응답/조회/확인 질문의 출력 계약을 분리한다. 집계 계약과 컬럼/지표 ID 공간도 명확히 한다.
3. 고정 입력의 양과 중복을 줄인다. 조직 후보와 지표 정의는 근거로 제공하되, 선택은 모델이 맡는다. 검색기 결과를 정답으로 자동 적용하지 않는다.
4. 같은 실패 사례에서 입력 구성·계약·모델을 한 번에 바꾸지 않고 비교한다. 실제 모델 테스트는 사용자와 합의한 범위에서만 실행한다. 기존 응답을 넣는 검사는 실제 자연어 능력 평가로 세지 않는다.

이 분석에서는 실행 코드를 수정하거나 새 모델을 실행하지 않았다.
