# 우사기 대화 연결 변경 — 2026-10-26

실제 대화 경로는 chat-dialogue → ConversationOrchestrator → Qwen이다.
Qwen이 일반 reply를 선택하면 Planner·Catalog·BI를 호출하지 않고 답한다.
도구 요청이나 조회 계획이면 첫 모델 출력을 그대로 QueryPlanner에 넘긴다. BI 여부 분류를 위해 모델을 한 번 더 부르는 구조가 아니다.
기존 실적 검색과 Rasa 호환 경로는 유지한다.

## 파일별 역할

- conversation-orchestrator.js: 첫 Qwen 응답, 일반 대화와 BI 실행 흐름 연결, 취소·시간 제한.
- conversation-context.js: 짧은 대화 입력, 활성 계획, 직전 실행 계획/지표/결과 요약, 대기 중 선택지.
- conversation-contract.js: 일반 답변·완성 조회·부분 수정·확인 질문의 생성 형식.
- clarification.js: 선택지가 실제 카탈로그 항목과 도구 결과에 근거하는지 검사. 후보를 자동 선택하지 않는다.
- query-planner.js: 도구 루프, 자체 수정, 반복 실패 중단, 시도별 오류·소요 시간 기록.
- live-bi-executor.js: 검증된 구조를 실제 BI 읽기 전용 조회식으로 변환. 필요한 경우 실제 열 값 후보를 조회하는 searchValues 제공.

직전 실행 계획은 biContext에 스냅샷으로 남긴다. 아직 조회하지 않은 조건 변경/선택지가 직전 실행 결과를 덮어쓰지 않는다.
일반 대화 도중에도 pendingClarification을 보존한다. 번호나 자연어를 특정 선택으로 해석하는 주체는 Qwen이며, 번호/표현별 JS 분기를 추가하지 않았다.
복수 대상은 in/prefix_any 집합 필터로 표현할 수 있다. 사용자 문장에서 브랜드를 추출하는 규칙이 아니라 실행 가능한 연산자의 확장이다.

## 속도와 확인 범위

전체 지표와 업무 정의를 매번 입력하지 않는다. 기본 카탈로그 응답은 5개이며, 상세 정의와 실제 값은 요청한 도구로만 읽는다.
의미 검색은 축약 인덱스로 후보를 좁힌 뒤 상세 근거를 반환한다. 이것은 추가학습이 아니며 최종 선택도 아니다.
일반 대화는 Qwen 응답 1회, BI는 첫 출력 재사용으로 불필요한 라우팅 호출을 피한다.

처음 대화의 시스템 입력은 문자 수 기준 약 5,000자에서 약 2,100자로 감소했다. 문자 수이며 토큰 수·속도 측정값이 아니다.
실제 Qwen 추론·BI 조회·학습을 실행하지 않았다. 테스트의 모델/BI 응답은 모의 응답이다.
따라서 실제 자연어 이해력이나 응답 시간이 개선됐다는 검증은 아직 아니다.
기존 사용자 교정 기록/실제 가중치 학습 파이프라인은 유지하며 자동 학습 활성화 상태도 바꾸지 않았다.
