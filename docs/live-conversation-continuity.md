# 실제 앱 대화·BI 경로 보완 (2026-10-26)

앱 기본 대화 엔진은 Qwen이다. USE_LLM_PLANNER=false를 명시한 경우에만 Rasa 호환 모드를 사용한다. 모델/BI 오류를 이유로 자동 전환하지 않는다. 화면에 현재 엔진과 실제 Power BI 실행 경로를 표시한다.
실제 채팅 생성에는 실제 query 함수 또는 명시적으로 주입한 executor가 필요하며, provider만 전달해 Fake를 암묵 생성하지 않는다.

## 카탈로그 탐색

catalog-index는 문자열·메타데이터의 겹침으로 후보 순서만 만든다. 문장→지표 매핑이나 의미 확정에는 사용하지 않는다.
searchCatalog는 기본 16개 후보의 이름·설명·정의를 Qwen에 한 번 전달하고, 최대 5개 근거 후보를 반환한다. 기존의 80개씩 전체 순회와 별도 rerank 호출을 제거했다.
검색 점수로 지표를 선택하거나 높은 점수를 확신도로 취급하지 않는다. main Qwen이 최종 선택/재질문을 결정한다.
부족하면 질문을 다듬거나 nextOffset으로 다음 후보 묶음을 요청할 수 있다. 한 묶음에 없다는 이유로 카탈로그 전체에 없다고 단정하지 않는다.

## 결과 표시와 설명

실제 BI 결과를 받은 뒤 bi:reply-progress로 표와 조회 기준을 먼저 표시한다. 원본 숫자와 표시값을 함께 보존한다.
같은 로컬 Qwen이 일부 결과와 기준을 보고 짧은 설명을 덧붙인다. 설명에 전체 카탈로그나 전체 대화 이력은 보내지 않는다.
설명은 최대 15초, 짧은 출력으로 제한한다. 설명 실패·시간 초과·숫자 근거 불일치·기록 저장 실패가 있어도 실제 BI 표는 반환하고 화면에 남긴다. Fake로 대체하지 않는다.
requestId로 현재 요청의 표만 갱신한다. 사용자가 초기화한 뒤 늦게 온 결과로 대화를 다시 채우지 않는다.
대화 타임스탬프에 전체 응답 시간과 첫 BI 결과까지 걸린 시간을 구분한다.

## 상태 보존

검증된 계획의 BI 실행이 성공한 뒤에만 활성 계획·필드 출처·직전 실행 결과를 확정한다.
BI 실패 시 기존 plan/biContext/pendingClarification은 유지하고, 실패한 제안은 lastFailedQuery에 별도로 남긴다. 다음 발화에서 Qwen이 그 요청을 이어받을 수 있다.
초기화와 명시적 취소는 기존 계약대로 처리한다.

개발 중 실제 Qwen 추론·실제 BI 로그인/조회·학습은 실행하지 않았다. 실제 사용자 테스트를 대신했다는 의미가 아니다.
